# 0.5.8 — 2026-10-10

## Changed

- **Tool failures** carry `data.requestId` for log correlation through the framework ([cyanheads/mcp-ts-core#576](https://github.com/cyanheads/mcp-ts-core/issues/576)).
- **Declared recovery** fills an absent hint through the framework; catalog-search and dataframe handlers drop redundant static forwards while preserving their existing hints ([cyanheads/mcp-ts-core#579](https://github.com/cyanheads/mcp-ts-core/issues/579)).
- **Development tooling** syncs framework skills, packaging checks, portable antipattern scans, CodeQL language categories, configuration examples, and environment/token ignore rules.

## Fixed

- **`bls_search_series`** accepts numeric-string `limit`/`offset`, boolean-string `seasonal_adjustment`, and null optional `area` through framework pre-validation ([cyanheads/mcp-ts-core#707](https://github.com/cyanheads/mcp-ts-core/issues/707)).
- **`bls_get_series`** accepts lone-string `series_ids`, numeric-string `start_year`/`end_year`, and boolean-string `calculations`/`annual_average`; **`bls_get_latest`** accepts lone-string `series_ids` through framework pre-validation.
- **Startup validation** reports invalid BLS configuration through the framework configuration banner before initializing services.
- **Registry npm entries** use the package executable; the HTTP entry fixes `MCP_TRANSPORT_TYPE=http` rather than passing npm-script arguments.
- **Docker production dependencies** cross-install on the build host, install declared OTel peers through a shipped script, and prune musl-only packages from the glibc runtime.
