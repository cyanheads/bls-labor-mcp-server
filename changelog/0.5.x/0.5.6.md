# 0.5.6 — 2026-09-23

## Changed

- **`request_rejected`** is raised only when BLS sends its generic rejection to both the request and its catalog-free re-issue; its recovery now says to retry once, then omit `calculations` or `annual_average` or change the year range, instead of splitting `series_ids`. ([#81](https://github.com/cyanheads/bls-labor-mcp-server/issues/81))
- **`bls_get_series` `format()`** — a series with no observations points to `enrichment.notice`, which carries its reason, instead of always suggesting `bls_search_series`. ([#80](https://github.com/cyanheads/bls-labor-mcp-server/issues/80))

## Fixed

- **A failed live fallback no longer discards mirror-served series** — when the observations mirror served at least one requested series with observations, `bls_get_series` returns it; each unserved SeriesID is a zero-observation entry, and `enrichment.notice` names it with the failure's reason (its message when untyped) and recovery. With nothing mirror-served, or a cancelled request, the live error propagates unchanged. ([#80](https://github.com/cyanheads/bls-labor-mcp-server/issues/80))
- **`bls_get_latest` keeps answered series on a request-level failure** — `invalid_api_key`, `quota_exceeded`, and `series_locked` are raised only when no requested series returned an observation; otherwise the affected SeriesIDs land in `failed[]` and the notice names the reason and recovery. ([#80](https://github.com/cyanheads/bls-labor-mcp-server/issues/80))
- **BLS's generic rejection** — with catalog metadata requested, BLS intermittently answers a request holding a nonexistent SeriesID with a series-less `REQUEST_FAILED`. Both live calls now re-issue such a request once without catalog metadata (one extra query, on that answer only) and fill title/area/item/seasonal from the catalog index where it holds the series. ([#81](https://github.com/cyanheads/bls-labor-mcp-server/issues/81))
- **`calculationsApplied`** is `false` when the observations mirror served any returned series, whose rows carry no BLS calculations; the notice names those series. ([#96](https://github.com/cyanheads/bls-labor-mcp-server/issues/96))
- **`register_as` column types** — the stored `column_schema` is the canvas's describe of the materialized table instead of all-`VARCHAR`, and a failed read fails the call. DuckDB `DECIMAL`, `HUGEINT`, `SMALLINT`, and list columns still report `VARCHAR` ([cyanheads/mcp-ts-core#500](https://github.com/cyanheads/mcp-ts-core/issues/500)). ([#71](https://github.com/cyanheads/bls-labor-mcp-server/issues/71))
- **Spill-table schema** — `bls_get_series` registers spills under a declared `SPILL_SCHEMA`: `value_numeric` and every `net_change_*` / `pct_change_*` column are `DOUBLE` whatever the batch holds, with BLS's calculation strings parsed to numbers. An available observation with a blank value now stores `NULL` in `value_numeric`, not `0`. ([#97](https://github.com/cyanheads/bls-labor-mcp-server/issues/97))
- **`bls_dataframe_drop` on a failed drop** — metadata goes only once the canvas confirms the drop or the table's absence; an acquire or provider failure throws a retryable `canvas_drop_failed` (`ServiceUnavailable`) and keeps the dataframe listed and queryable, instead of reporting `dropped: true`. ([#74](https://github.com/cyanheads/bls-labor-mcp-server/issues/74))
- **TTL sweep** — an expired dataframe the sweep cannot drop keeps its metadata, logs a warning, and is retried by the next operation. The shared canvas is replaced only when its stored id reports `canvas_not_found`, not on any acquire failure. ([#74](https://github.com/cyanheads/bls-labor-mcp-server/issues/74))
- **Invalid dataframe names** — `bls_dataframe_drop` rejects a `name` outside `CANVAS_IDENTIFIER_REGEX` or a reserved SQL keyword; `bls_dataframe_describe` raises `invalid_dataframe_name` (`InvalidParams`) for a non-blank name outside the rule, and a blank one still lists every dataframe. Both previously failed with the storage-key message. ([#99](https://github.com/cyanheads/bls-labor-mcp-server/issues/99))
