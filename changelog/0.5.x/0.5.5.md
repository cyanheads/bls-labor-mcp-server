# 0.5.5 — 2026-09-23

**Upgrade:** `CATALOG_INDEX_VERSION` is now `3`, so an index persisted by an earlier release gains the `frequency` column and re-harvests once on its first boot after upgrade; searches keep reading its existing rows, without `frequency`, until that harvest completes. The hourly `bls-catalog-refresh` job now runs in every process, on both transports, and `node-cron` is a new runtime dependency.

## Added

- **`frequency` on `bls_search_series` results** — CU, CW, and LN decode `periodicity_code` through `{abbr}.periodicity` into `Monthly`, `Semi-Annual`, `Quarterly`, or `Annual`, telling apart series that share one title; `format()` renders it beside the seasonal flag. A query naming `monthly`, `quarterly`, or `semiannual` (`semi-annual`, `semi annual`) as a whole word lifts rows of that frequency; `annual` is never matched. ([#85](https://github.com/cyanheads/bls-labor-mcp-server/issues/85))
- **CM (ECEC) and CI (ECI) in the catalog** — both decode `area` through `{abbr}.area` and `item` through `{abbr}.estimate`, and sit last in `SURVEY_ABBRS`; the default index grows to ~170K series across 14 surveys. `United States (National)` joins `NATIONAL_AREAS`, and the opt-in observations mirror now also harvests `cm.data.*` / `ci.data.*` (~55 MB). ([#86](https://github.com/cyanheads/bls-labor-mcp-server/issues/86))
- **`bls-catalog-refresh`** — an hourly (`0 * * * *`) `schedulerService` job registered by `scheduleBlsCatalogRefresh()` whose tick calls `load()`, so a running process re-harvests once `BLS_CATALOG_CACHE_TTL_HOURS` lapses; concurrent `load()` calls share one in-flight run. ([#84](https://github.com/cyanheads/bls-labor-mcp-server/issues/84))

## Changed

- **Compensation aliases** — `compensation`, `employer cost`, and `ecec` now route to CM and CI, and `employment cost index` / `eci` to CI, instead of the discontinued EC, which stays indexed and reachable with `survey: "EC"`. ([#86](https://github.com/cyanheads/bls-labor-mcp-server/issues/86))
- **Catalog shutdown** — `shutdownBlsCatalogService()` removes the refresh job, then aborts any in-flight harvest before closing the store, so no write follows teardown. ([#84](https://github.com/cyanheads/bls-labor-mcp-server/issues/84))

## Fixed

- **Stale catalog rows** — after a survey's upserts, its rows absent from the new `.series` file are deleted, as are rows of surveys no longer configured (OE once its opt-in turns off). A survey whose `.series` request fails, returns non-200, lacks a `series_id` header column, or ends mid-line (a truncated download) keeps its rows, and a harvest that applies no rows deletes nothing. Deletes run in 5,000-row transactions like the upserts, yielding the event loop between chunks. ([#84](https://github.com/cyanheads/bls-labor-mcp-server/issues/84))
- **Configuration changes inside the TTL** — each completed harvest stores its survey list in the sync state's `checkpoint`, and `load()` treats a missing or different list as stale, so toggling `BLS_CATALOG_INCLUDE_OES` re-harvests on the next boot. ([#84](https://github.com/cyanheads/bls-labor-mcp-server/issues/84))
- **`node-cron` is a declared dependency** — HTTP startup with `BLS_OBSERVATIONS_MIRROR_ENABLED=true` no longer fails on an install without it, and the catalog refresh job needs it on every transport. ([#88](https://github.com/cyanheads/bls-labor-mcp-server/issues/88))
- **Concept aliases match at word starts** — `ppi` no longer fires inside "shopping" or "happiness"; a stem phrase such as `job vacanc` still matches its completions. ([#89](https://github.com/cyanheads/bls-labor-mcp-server/issues/89))
- **Rescore tokens match at word starts** — the query and its tokens count in a title, area, item, or headline description only where a word starts (SeriesID fragments still match anywhere), and a `COMMON_SERIES` headline earns its +8 only when its survey's alias fires or it matches more than half the distinct tokens, so `annual average all items` no longer puts the CES, PPI, or JOLTS headlines in its top 5. ([#91](https://github.com/cyanheads/bls-labor-mcp-server/issues/91))

## Security

- **`bls_search_series` search cost is bounded** — a long or repetitive `query` held the process's event loop for seconds (12.6 s for a 3,200-character query), stalling every other request. The FTS match and the rescore now use each distinct token once, at most `MAX_QUERY_TOKENS` (32), bounding a search at ~0.7–0.8 s on the 2026-09-23 index; an `area` longer than 1,000 characters matches nothing and skips the FTS query. ([#92](https://github.com/cyanheads/bls-labor-mcp-server/issues/92))

## Dependencies

- **`node-cron` ^4.6.0** — added, the optional peer the framework's `schedulerService` loads. ([#88](https://github.com/cyanheads/bls-labor-mcp-server/issues/88))
